Why a cursor and not ?page=3?

Page numbers shift when rows are inserted between requests — you silently skip or duplicate records. A cursor pins your position in the stream instead.

05Pathologies by design

Clean data teaches nothing. Every quirk below is intentional — each one is a downstream exercise in disguise.

nulls

Walk-in customers

~30% of sales have customer_id = NULL. Joins to dim_customers must decide: drop, keep, or bucket — and aggregations over NULL keys create a fat skewed partition.

sentinel

The zero that means nothing

work_order_items uses 0 for the unused service/product FK. Silver converts it to proper NULL — a classic source-system smell you get to clean.

idempotency

Re-runs write duplicates

Same date re-run = identical rows, new random file names. Auto Loader happily ingests both. The silver insert-only MERGE is what makes the pipeline idempotent — bronze is deliberately not.

skew

Weighted everything

Payment methods, statuses, cities, car makes — all drawn from realistic weighted distributions (reference_data.py). Perfect raw material for salting and AQE experiments.

quality gate

Quarantine, not silent drops

Silver builds a _reject_reason per rule; rejects are appended to *_quarantine tables. Bad data is evidence, not garbage.

types

date32 discipline

Every date column is built from real datetime.date objects so parquet gets date32, matching the Delta DATE declaration — not a datetime64 timestamp in disguise.

06Governance: how ADLS gets plugged in

External storage is never "just a path". Unity Catalog chains four objects between a query and the bytes — no keys, no secrets, no Spark conf:

Access Connector
Azure managed identity + RBAC on the storage account
→
Storage Credential
UC object wrapping the connector
→
External Location
abfss:// path × credential = authorization zone
→
Volume / Table
files via /Volumes/…, Delta tables on your own path

This is not a demo corner of the repo: all 20 tables are external (each CREATE TABLE carries a LOCATION under tables/), and dimension snapshots land on the dim_landing external volume — so every byte of the platform lives on storage this chain governs. Worth knowing: DROP TABLE on an external table removes metadata only; re-creating it at the same path resurrects the data from _delta_log.

The whole chain is code: an az-cli walkthrough, plain SQL, and a Terraform module that replaces both.
