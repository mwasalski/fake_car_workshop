# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Synthetic "car workshop" data platform for practising Spark / Data Engineering on
Databricks (medallion architecture), plus the owner's exam & interview training material
(certifications: Spark Developer Associate, Databricks DE Professional; long-term goal:
Data Architect). Code, comments and docs are **English only**; the owner communicates in
Polish. Everything executes on Databricks against Unity Catalog catalog `car_workshop`
(`dim` / `fact` / `silver` / `lab` schemas) — notebooks need `spark` and `dbutils` and
**cannot run locally**.

## Pipeline architecture

```text
create_tables.sql   (once)   catalog, schemas, volumes, 20 empty Delta tables
initial_dims.ipynb  (once)   7 dims -> parquet on /Volumes/car_workshop/dim/dim_landing (seed 42;
                             file -> dim.* ingestion is a separate, not-yet-built step)
daily.ipynb         (daily)  13 fact tables -> parquet on /Volumes/car_workshop/fact/fact_files
autoloader.ipynb    (daily)  Auto Loader (cloudFiles) -> car_workshop.fact.*  (dims do NOT flow through it)
silver/             (daily)  bronze -> car_workshop.silver.* (streaming foreachBatch + MERGE)
run_all.ipynb                %run orchestrator: one-time setup + daily cycle
backfill.ipynb               daily.ipynb per date via dbutils.notebook.run (parallel)
```

Key mechanics that span multiple files:

- **Determinism & ID uniqueness**: `daily.ipynb` seeds RNG with `TARGET_DATE` and gives
  every day a disjoint 10M ID block per table (`ID_START = days_since_2020-01-01 × ID_BLOCK`).
  Re-running a date reproduces identical rows but writes duplicate files.
  Largest per-day row count must stay `< ID_BLOCK` (asserted).
- **Widgets**: `TARGET_DATE` (blank = yesterday) and `SCALE_FACTOR` (blank = 1.0 ≈ 100K
  rows/day) — `backfill.ipynb` passes both through and uses `fact_employee_schedules`
  files as the per-date completion marker (daily writes that table last).
- **Silver pattern** (`silver/silver_sales.ipynb` is the reference): stream bronze table →
  `foreachBatch` → dedup in batch → quality rules building `_reject_reason` → rejects
  appended to `*_quarantine` → valid rows via **insert-only MERGE** (idempotent). CDF
  enabled. The remaining silver tables are the owner's intentional exercises — do not
  pre-build them unasked.
- **Semantics**: `customer_id IS NULL` in sales = walk-in customer (~30%, deliberate skew
  material); `work_order_items` uses `0` sentinel for the unused service/product FK
  (silver converts to NULL). Facts are hive-partitioned per `PARTITIONED_TABLES`;
  silver drops `year`/`month` and uses liquid clustering.

## Single sources of truth

- `table_schemas.py` — column→type dicts for all 20 tables + `PARTITIONED_TABLES` +
  `schema_to_ddl()` / `build_spark_schema()`. Must stay in sync with `create_tables.sql`.
- `reference_data.py` — every dictionary, status list and weight used by generators.
  New option lists belong here, never inline in notebooks.
- Notebooks import these from the same directory (works in Databricks Repos) — the repo
  must land in Databricks as a whole.

## Working on this repo

- Notebooks are plain nbformat JSON with cell `source` as single strings. After editing
  them programmatically, syntax-check every code cell (skip `%`/`!` magic cells):

  ```bash
  python3 -c "
  import json
  nb = json.load(open('daily.ipynb'))
  [compile(c['source'], 'c', 'exec') for c in nb['cells']
   if c['cell_type'] == 'code' and not c['source'].lstrip().startswith(('%', '!'))]"
  ```

- `reference_data.py` / `table_schemas.py` are locally compile-checkable
  (`python3 -m py_compile`); nothing else runs off-Databricks.
- Date columns must reach parquet as `date32`: build them from `datetime.date` objects
  (`np.full(n, TARGET_DATE)`, `(pd.Timestamp(...) + pd.to_timedelta(...)).date`) —
  never leave them as `datetime64` timestamps, the Delta tables declare `DATE`.
- Reset procedure lives in `README.md` (truncate facts + clear volume files and
  Auto Loader/silver checkpoints; dims are just re-overwritten by `initial_dims.ipynb`).
- Work happens on branch `new-arch`; the owner commits and pushes himself.
- `learning/spark_deep_dive.ipynb`: cells marked `CLASSIC CLUSTER ONLY` flip Spark confs
  or use the RDD API (blocked on serverless); each has a serverless variant cell right
  below. Lab objects go to the disposable `car_workshop.lab` schema.
- `car_workshop_ab/` is an untouched `databricks bundle init` scaffold (sample taxis
  code) reserved for future DABs work; root `databricks.yml` was generated by the
  VS Code Databricks extension.
- `testing/tables_checker.ipynb` contains destructive `%sql DELETE` cells — never chain
  it into automation.
